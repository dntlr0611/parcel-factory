# Parcel Factory — 설계 문서

작성일: 2026-10-15 · 개정 2026-10-16 (9절)
상태: 1차 범위 승인됨, 9절 개정안 검토 중

## 1. 개요

2D 공장 부지에 택배 레일을 설치해 입고된 택배를 출고 트럭까지 운반하는 실시간 경영 게임.
플레이어는 돈을 벌어 새 부품과 부지를 해금하고, 레일 배치를 바꿔 처리량을 늘린다.

- 플랫폼: PC (마우스 + 키보드)
- 엔진: Unity 6.3 LTS (6000.3.x), C#, URP 3D. 9.4절 참고: 2D 격자 게임플레이를 3D 로우폴리로 렌더링한다.
- 진행: 실시간, 일시정지와 배속 가능
- 1차 범위: 공장 1개

## 2. 핵심 루프

1. 입고구에서 일정 주기로 택배가 생성된다.
2. 택배는 레일을 따라 이동한다.
3. 출고구(트럭)에 도착하면 판매되어 잔액이 늘어난다.
4. 레일이 끊긴 곳에서 떨어지면 택배는 소실된다 (수익 0, 추가 손실 없음).
5. 플레이어는 잔액으로 부품을 설치하고, 해금 상점에서 새 부품·부지를 산다.

## 3. 규칙

### 3.1 그리드
- 크기 12×12. 원점 (0,0)은 좌측 하단이며 y는 위로 증가한다. 초기 해금 영역은 x, y 모두 0 이상 6 미만인 6×6.
- 셀 상태: `Empty`, `Conveyor(dir)`, `FastConveyor(dir)`, `Splitter(dir)`, `Inlet`, `Outlet`, `Locked`. (이후 추가: `Table`·`Scanner`·`ReturnDock`은 9절, `Pallet`은 10.2)
- 부품이 있는 셀은 `Demolishing` 플래그와 남은 시간을 가질 수 있다 (3.3 참고).
- 입고구는 (0,2)에 고정 배치. 출고구·반품구는 **10.1에 따라 동쪽 벽 트럭 도크 (11,2)·(11,4)**로 옮겼고, 옛 자리 (5,2)·(5,4)에는 시작 팔레트(10.2)가 놓인다. 도크는 부지를 확장해도 위치가 바뀌지 않으며, 잠긴 구역에 있어도 처음부터 존재하고 플레이어가 철거할 수 없다.
- 방향: `North`, `East`, `South`, `West` 4방향.

### 3.2 부품

| 부품 | 설치비 | 동작 | 초기 해금 |
|---|---|---|---|
| 레일 (방향별) | 10 | 방향으로 택배를 전진시킴 | 동쪽만 |
| 고속 레일 (방향별) | 25 | 레일의 2배 속도 | 아니오 |
| 분배기 | 60 | 들어온 택배를 분배기 방향 기준 좌·우 출구로 번갈아 보냄. 들어온 방향의 정반대로는 절대 보내지 않음(그 경우 다른 출구 사용) | 아니오 |

- 레일과 고속 레일은 **방향마다 별도 도구**다. 툴바에 "레일 →", "레일 ↓" 처럼 방향별 버튼이 있고, 각 방향은 상점에서 따로 해금한다. 회전 키는 없다.
- 코너는 별도 부품이 없다. 동쪽으로 향하는 레일이 남쪽으로 향하는 레일로 이어지면 택배가 그대로 방향을 바꾼다.
- 레일 한 칸에는 택배가 최대 1개. 다음 칸이 점유되어 있으면 현재 칸 끝에서 대기한다.
- 레일이 가리키는 다음 칸이 레일·분배기·출고구가 아니면 택배는 소실된다.

### 3.3 경제
- 시작 잔액: 100.
- 택배 1개 배송: 정상 출고 +30, 불량 반품 +10 (2026-10-20 개정: 9.3 표 참고. 설치비·해금비와의 간격을 줄이기 위해 15/5에서 올림).
- 설치: 잔액에서 설치비 차감. 잔액 부족 시 설치 불가.
- 해체: 우클릭으로 시작하면 **2초**가 걸린다. 완료 시 설치비의 **80%를 환불**한다. 추가 비용은 없다.
- 해체 중인 칸은 새 택배를 받지 않는다. 이미 올라가 있던 택배는 계속 이동하며, 완료 시점까지 남아 있으면 소실된다.
- 해체는 취소할 수 없다. 일시정지 중에는 해체 타이머도 멈춘다.

### 3.4 해금 상점

| 항목 | 가격 | 효과 |
|---|---|---|
| 부지 확장 1 | 200 | 해금 영역을 9×9로 확장 |
| 부지 확장 2 | 500 | 해금 영역을 12×12로 확장 (확장 1 이후) |
| 레일 남/서/북 | 각 50 | 해당 방향 레일 도구 추가 (동쪽은 시작부터 보유) |
| 고속 레일 동/남/서/북 | 각 100 | 해당 방향 고속 레일 도구 추가 |
| 분배기 | 300 | 툴바에 분배기 추가 |

해금 항목은 총 10개. 각 항목은 한 번만 구매할 수 있다.

### 3.5 시간
- 시뮬레이션 틱: 고정 20Hz (0.05초).
- 속도: 일시정지 / 1x / 2x. 일시정지 중에도 설치·해체는 가능하다.
- 입고 주기: 처음 8초에 1개. 성공 배송(출고 +15, 반품 +5) 5건마다 0.5초씩 빨라져 50건부터 3초에 1개(최소). (2026-10-20 개정: 초반이 너무 빨랐음)
- 레일 이동 속도: 1칸/초. 고속 레일 2칸/초.
- 해체 소요 시간: 2초 (시뮬레이션 시간 기준, 배속 영향 받음).

## 4. 구조

### 4.1 코어 (순수 C#, `Assets/Scripts/Core/`, asmdef `ParcelFactory.Core`)

MonoBehaviour와 UnityEngine 의존이 없다. EditMode 테스트 대상.

- `Direction` — 4방향 enum과 오프셋·회전 유틸.
- `CellType`, `Cell` — 셀 상태와 방향.
- `FactoryGrid` — W×H 셀 배열. `IsUnlocked(x,y)`, `Place`, `Remove`, `Get`.
- `PackageKind` — `Normal` (2차에서 `Fragile`, `Large` 추가 예정).
- `Package` — id, kind, 현재 셀 좌표, 진행도(0~1), 이동 중 방향.
- `Package.EntryHeading` — 현재 셀에 들어온 방향. 렌더링에서 코너를 부드럽게 그리는 데 쓴다.
- `ConveyorSim` — `Tick(dt)`: 모든 택배를 전진시키고 점유·배송·소실을 처리. 이벤트: `PackageDelivered`, `PackageLost`.
- `Spawner` — 입고 주기마다 입고구에 택배 생성. 입고구 앞 칸이 점유 중이면 건너뛴다.
- `Economy` — `Money`, `TrySpend(amount)`, `Earn(amount)`.
- `BuildService` — 설치 규칙 검증 후 `FactoryGrid`와 `Economy`를 갱신. 해체 시작(`BeginDemolish`)과 매 틱 타이머 진행(`TickDemolitions`), 완료 시 80% 환불 처리.
- `Toolbar` 상태 — 보유한 도구 목록 (부품 종류 + 방향). `UnlockService`가 구매 시 추가한다.
- `UnlockCatalog`, `UnlockService` — 해금 항목 정의와 구매 처리. 부지 확장은 `FactoryGrid.UnlockRegion`을 호출.
- `GameState` — 위 상태를 담는 직렬화 DTO. `SaveSerializer`가 JSON으로 변환·복원.
- 2차 분류 기능의 확장 지점은 `PackageKind` enum이다. 1차에서 출고구는 모든 종류를 받는다.

### 4.2 Unity 레이어 (`Assets/Scripts/Game/`, asmdef `ParcelFactory.Game`)

- `GameLoop` — `FixedUpdate` 대신 자체 누적기로 20Hz 틱 호출. 속도 배율과 일시정지 보유.
- `GridView` — Tilemap 2개(바닥, 부품). 잠긴 셀은 어두운 타일. 레일 타일은 방향별 스프라이트.
- `PackageView` — 오브젝트 풀. 코어의 셀 좌표 + 진행도를 월드 좌표로 보간.
- `BuildController` — 입력 처리. 툴바에서 방향별 도구 선택, 호버 고스트, 좌클릭 설치, 우클릭 해체 시작(확인 팝업에 환불액과 소요 시간 표시). 해체 중인 셀은 진행 바를 띄운다.
- `HudView` (IMGUI, `OnGUI`) — 잔액, 속도 버튼, 툴바, 해금 상점 패널, 저장/불러오기 버튼, 토스트, 해체 확인 팝업과 진행 바. 씬 편집 없이 코드만으로 구성하기 위해 1차는 IMGUI를 쓴다.
- `SaveFile` — `Application.persistentDataPath/save.json` 읽기·쓰기.

데이터 흐름: 입력 → `BuildController` → 코어 서비스 → 코어 이벤트 → 뷰 갱신. 뷰는 코어를 읽기만 하고, 코어는 뷰를 모른다.

## 5. 오류 처리

- 설치 실패(잔액 부족, 잠긴 칸, 점유된 칸): HUD에 1초 토스트로 사유 표시. 상태 변화 없음.
- 저장 파일 손상 또는 없음: 불러오기 실패 시 현재 세션을 유지하고 토스트로 사유를 알림.
- 저장 실패(IO 오류): 임시 파일에 쓴 뒤 교체하며, 실패 시 기존 파일을 유지하고 토스트로 알림.
- 저장 파일에 버전 필드를 두고, 불일치 시 불러오기를 거부한다.

## 9. 개정 (2026-10-16): 작업자 중심 플레이, 검사, 등각 픽셀아트

참고: Steam 〈Parcel Simulator〉의 루프(입고 → 라벨 검사 → 분류 → 출고, 장비 구매로 자동화)를 2D 정면 3/4 시점 픽셀아트로 옮긴다. 아래 항목은 1차 범위에 **추가**되며, 3~6절과 충돌하는 부분은 이 절이 우선한다. 화면 시안: https://claude.ai/artifact/M5jkC6DBgZkEn1ccq5v8PP

### 9.1 플랫폼과 조작
- PC(마우스+키보드)와 모바일(터치, **가로** 고정) 둘 다 지원한다.
- 플레이어는 공장 안을 걸어 다니는 **작업자**를 직접 조종한다. 설치·해체·집기·놓기·검사는 모두 작업자가 **바라보는 칸**에 대해 수행한다. 클릭으로 아무 칸이나 설치하는 방식은 폐기한다.
- PC: WASD/방향키 이동(상하좌우), E = 상호작용(집기/놓기/설치/검사), X = 해체, 숫자키 또는 클릭으로 도구 선택.
- 모바일: 왼쪽 하단 D-패드(상하좌우 십자), 오른쪽 하단 큰 상호작용 버튼과 해체 버튼, 오른쪽 상단 도구함 목록, 상점은 상단 바 버튼. 터치 타깃 44px 이상.
- ~~작업자는 빈 바닥 칸만 걸을 수 있다.~~ → **9.7로 대체(2026-10-16 저녁 개정)**: 작업자는 격자에 묶이지 않고 부드럽게 걸으며, 레일과 도크 위는 지나갈 수 있다.

### 9.2 수작업 운반
- 작업자는 택배를 **1개** 들 수 있다. 바라보는 칸(입고구, 레일, 검사대 등 트랙)에 택배가 있으면 집고, 들고 있는 상태에서 빈 트랙 칸을 바라보고 놓으면 그 칸의 방향으로 다시 흐른다.
- 들고 있는 택배를 출고구·반품구에 직접 놓으면 그 자리에서 배송 판정(9.3)이 이뤄진다. 초반에는 레일 없이 손으로 나르는 플레이가 가능해야 한다.
- 택배를 들고 있는 동안 부품 설치는 불가.

### 9.3 검사와 분류
- 택배는 생성 시 30% 확률로 **불량**(표기 무게와 실측이 다름)이다. 겉모습으로는 구분되지 않는다.
- 새 부품 **검사대**(설치비 40, 시작부터 보유, 방향 있음): 택배가 올라오면 검사 전까지 멈춘다. 작업자가 검사대를 바라보고 상호작용하면 라벨 카드(목적지, 표기 무게, 배송 방법, 저울 실측)가 뜨고 **승인/거부**를 고른다. 판정 후 택배는 `inspected`, `rejected` 상태를 갖고 검사대 방향으로 계속 흐른다.
- 해금 항목 **자동 검사기**(해금 250, 설치비 120, 4방향): 레일처럼 흐르면서 진입(또는 작업자가 내려놓는) 즉시 정확히 판정한다. 1차에서는 오판 없음. 이미 사람이 판정한 택배는 다시 판정하지 않는다.
- 새 고정 도크 **반품구**: (5,4)에 고정. 출고구처럼 택배를 받는다.
- 배송 판정(출고구 / 반품구):

| 택배 상태 | 출고구 | 반품구 |
|---|---|---|
| 검사 안 함 | −10 | −5 |
| 승인·정상 | **+30** | −5 |
| 승인·불량 | −30 | −5 |
| 거부·불량 | −10 | **+10** |
| 거부·정상 | −10 | −5 |

- 잔액은 음수가 될 수 있다(파산 조건은 2차에서 정한다).

### 9.7 작업자 자유 이동 (2026-10-16 저녁 개정, 9.1 다섯째 항목을 대체)
- 작업자 위치는 **연속 좌표**(칸 단위 float, 칸 중심이 정수)다. 입력은 누르고 있는 동안 계속 적용되며 8방향(대각 이동 시 속도 정규화). 속도 3.4칸/초, 충돌 반지름 0.28칸.
- 걸을 수 있는 곳: 해금된 n×n 부지 안의 빈 칸, **레일·고속 레일·입고구·출고구·반품구 위**. 막는 것: 검사대, 분배기, 자동 검사기, 미해금 칸, 부지 경계. 레일 위에 서 있어도 택배 흐름에는 영향이 없고 작업자가 벨트에 실려 가지도 않는다.
- 충돌은 축별로 따로 처리한다(x 이동 → 막히면 취소, y 이동 → 막히면 취소). 그래서 벽을 따라 미끄러진다.
- 바라보는 방향은 마지막 이동 벡터의 지배 축으로 정한다(|vx| ≥ |vy| → 동/서, 아니면 북/남). 바라보는 칸 = `round(위치 + 방향 × 0.8)`. 상호작용·설치·해체·검사는 모두 이 칸에 대해 수행한다.
- 설치 제한: 막는 부품(검사대·분배기·자동 검사기)은 작업자의 충돌원과 겹치는 칸에 놓을 수 없다(`InteractResult.Standing`). 레일은 작업자가 서 있는 칸에도 놓을 수 있다.
- 모바일: D-패드는 **누르고 있는 동안** 이동(탭 1회 = 1칸 방식 폐기).
- 코어 변경: `Worker.X/Y`를 float로, `WorkerService.Move(vx, vy, dt)`가 `TryMove(dir)`를 대체, `FacingTile()`은 위의 규칙, `GameState` v3(작업자 좌표 float; v2 저장은 칸 중심으로 변환해 읽는다). 이동 중에는 `CancelInspection()`.

## 10. 개정 (2026-10-20): 트럭 도크와 팔레트 — 수작업 출고, 확장하면 자동화

사용자 결정: 출고·반품은 "자동으로 연결"되지 않는다. 파란/빨간 칸은 택배가 **쌓이는 팔레트**이고, 작업자가 거기서 택배를 집어 **트럭까지** 직접 나른다. 부지를 동쪽 벽까지 넓히면 레일을 트럭 도크에 바로 붙여 자동화할 수 있다. 3.1·9.5·9.7과 충돌하는 부분은 이 절이 우선한다.

### 10.1 트럭 도크 (판정 지점)
- `Outlet`은 (11,2), `ReturnDock`은 (11,4)로 옮긴다. 동쪽 벽 출입구 바로 안쪽 칸이며 차량이 그 밖에 후진 주차되어 있다. 해금 여부와 무관하게 처음부터 존재하고 철거할 수 없다. 입고구는 (0,2) 그대로.
- 레일이 닿아 흘러 들어오거나 작업자가 손으로 놓으면 **그 자리에서** 9.3 판정표대로 판정한다. 판정은 트럭 도크에서만 일어난다.
- 12칸까지 해금하면 (10,2)·(10,4)에 동향 레일을 두어 트럭으로 자동 투입할 수 있다. 그 전에는 (6..10, ·)이 잠겨 있어 레일을 못 놓으므로 손으로 날라야 한다.

### 10.2 팔레트 (적재대)
- 새 부품 `Pallet`: 설치비 20, 시작부터 보유, 해체 2초·환불 80%. 방향 대신 **종류**가 있다: `Blue`(출고 대기)·`Red`(반품 대기). 색은 안내용이며 판정과 무관하다. 도구 표현은 기존 `Tool(Type, Direction)`을 재사용해 `East = Blue`, `West = Red`로 매핑하고, R(또는 슬롯 재탭)로 종류를 순환한다.
- 시작 배치: (5,2) Blue, (5,4) Red가 미리 설치되어 있다(옛 출고구·반품구 자리). 플레이어가 해체하거나 옮길 수 있다.
- 용량 6. 레일에서 흘러 들어온 택배는 흐름에서 빠져 팔레트 더미에 쌓인다(검사 상태 유지). 가득 차면 앞 레일의 택배는 대기한다. 팔레트에서 레일로 자동 유출은 없다.
- 작업자가 팔레트를 바라보고 E → 맨 위 택배를 집는다. 들고 있는 택배를 팔레트에 놓을 수도 있다(용량 내). 팔레트 위에 택배가 있으면 해체할 수 없다(`Occupied`).
- 팔레트는 걸어서 지나갈 수 없다.

### 10.3 걷기와 설치 범위
- 건물 안 12×12는 **전부 걸어 다닐 수 있다**(잠긴 칸 포함; 바닥일 뿐이다). 9.7의 "부지 경계"는 격자 경계로 바뀐다. 막는 것은 검사대·분배기·자동 검사기·팔레트뿐이다.
- 설치는 해금된 칸에만 가능하다(변경 없음). 트럭 도크 칸은 항상 상호작용(놓기) 가능하다.

### 10.4 HUD·월드
- 핫바는 종류당 1칸, 순서: 레일, 고속 레일, **팔레트**, 검사대, 분배기, 자동 검사기 → 최대 6칸, 키 1~6. 팔레트 칸은 화살표 대신 "파랑/빨강"을 표시한다.
