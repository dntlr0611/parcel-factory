# Parcel Factory — 설계 문서

작성일: 2026-10-15
상태: 승인됨 (1차 범위)

## 1. 개요

2D 공장 부지에 택배 레일을 설치해 입고된 택배를 출고 트럭까지 운반하는 실시간 경영 게임.
플레이어는 돈을 벌어 새 부품과 부지를 해금하고, 레일 배치를 바꿔 처리량을 늘린다.

- 플랫폼: PC (마우스 + 키보드)
- 엔진: Unity 6 LTS, 2D URP, C#
- 진행: 실시간, 일시정지와 배속 가능
- 1차 범위: 공장 1개

## 2. 핵심 루프

1. 입고구에서 일정 주기로 택배가 생성된다.
2. 택배는 레일을 따라 이동한다.
3. 출고구(트럭)에 도착하면 판매되어 잔액이 늘어난다.
4. 레일이 끊긴 곳에서 떨어지면 택배는 소실된다 (수익 0, 추가 손실 없음).
5. 플레이어는 잔액으로 부품을 설치하고, 해금 상점에서 새 부품·부지를 산다.

## 3. 규칙

### 3.1 그리드
- 크기 12×12. 초기 해금 영역은 좌측 상단 6×6.
- 셀 상태: `Empty`, `Conveyor(dir)`, `Splitter(dir)`, `Inlet`, `Outlet`, `Locked`.
- 입고구는 (0,2), 출고구는 (5,2)에 고정 배치. 부지를 확장해도 위치는 바뀌지 않으며, 플레이어가 철거할 수 없다.
- 방향: `North`, `East`, `South`, `West` 4방향.

### 3.2 부품

| 부품 | 설치비 | 동작 | 초기 해금 |
|---|---|---|---|
| 레일 | 10 | 방향으로 택배를 전진시킴 | 예 |
| 고속 레일 | 25 | 레일의 2배 속도 | 아니오 |
| 분배기 | 60 | 들어온 택배를 좌·우 출구로 번갈아 보냄 | 아니오 |

- 코너는 별도 부품이 없다. 동쪽으로 향하는 레일이 남쪽으로 향하는 레일로 이어지면 택배가 그대로 방향을 바꾼다.
- 레일 한 칸에는 택배가 최대 1개. 다음 칸이 점유되어 있으면 현재 칸 끝에서 대기한다.
- 레일이 가리키는 다음 칸이 레일·분배기·출고구가 아니면 택배는 소실된다.

### 3.3 경제
- 시작 잔액: 100.
- 택배 1개 배송: +15.
- 설치: 잔액에서 설치비 차감. 잔액 부족 시 설치 불가.
- 해체: 설치비의 10%를 잔액에서 차감한다. 환불은 없다. 잔액이 10% 비용보다 적으면 해체 불가.
- 해체 중인 칸 위의 택배는 소실된다.

### 3.4 해금 상점

| 항목 | 가격 | 효과 |
|---|---|---|
| 부지 확장 1 | 200 | 해금 영역을 9×9로 확장 |
| 부지 확장 2 | 500 | 해금 영역을 12×12로 확장 (확장 1 이후) |
| 고속 레일 | 150 | 툴바에 고속 레일 추가 |
| 분배기 | 300 | 툴바에 분배기 추가 |

### 3.5 시간
- 시뮬레이션 틱: 고정 20Hz (0.05초).
- 속도: 일시정지 / 1x / 2x. 일시정지 중에도 설치·해체는 가능하다.
- 입고 주기: 3초에 1개.
- 레일 이동 속도: 1칸/초. 고속 레일 2칸/초.

## 4. 구조

### 4.1 코어 (순수 C#, `Assets/Scripts/Core/`, asmdef `ParcelFactory.Core`)

MonoBehaviour와 UnityEngine 의존이 없다. EditMode 테스트 대상.

- `Direction` — 4방향 enum과 오프셋·회전 유틸.
- `CellType`, `Cell` — 셀 상태와 방향.
- `FactoryGrid` — W×H 셀 배열. `IsUnlocked(x,y)`, `Place`, `Remove`, `Get`.
- `PackageKind` — `Normal` (2차에서 `Fragile`, `Large` 추가 예정).
- `Package` — id, kind, 현재 셀 좌표, 진행도(0~1), 이동 중 방향.
- `ConveyorSim` — `Tick(dt)`: 모든 택배를 전진시키고 점유·배송·소실을 처리. 이벤트: `PackageDelivered`, `PackageLost`.
- `Spawner` — 입고 주기마다 입고구에 택배 생성. 입고구 앞 칸이 점유 중이면 건너뛴다.
- `Economy` — `Money`, `TrySpend(amount)`, `Earn(amount)`.
- `BuildService` — 설치·해체 규칙 검증 후 `FactoryGrid`와 `Economy`를 함께 갱신. 해체 비용 계산 포함.
- `UnlockCatalog`, `UnlockService` — 해금 항목 정의와 구매 처리. 부지 확장은 `FactoryGrid.UnlockRegion`을 호출.
- `GameState` — 위 상태를 담는 직렬화 DTO. `SaveSerializer`가 JSON으로 변환·복원.
- `OutletCell.AcceptedKinds` — 1차에서는 모든 종류 허용. 2차 분류 기능의 확장 지점.

### 4.2 Unity 레이어 (`Assets/Scripts/Game/`, asmdef `ParcelFactory.Game`)

- `GameLoop` — `FixedUpdate` 대신 자체 누적기로 20Hz 틱 호출. 속도 배율과 일시정지 보유.
- `GridView` — Tilemap 2개(바닥, 부품). 잠긴 셀은 어두운 타일. 레일 타일은 방향별 스프라이트.
- `PackageView` — 오브젝트 풀. 코어의 셀 좌표 + 진행도를 월드 좌표로 보간.
- `BuildController` — 입력 처리. 툴 선택, 호버 고스트, 좌클릭 설치, `R` 또는 마우스 휠로 회전, 우클릭 해체(비용 확인 팝업).
- `HudView` (UGUI) — 잔액, 속도 버튼, 툴바, 해금 상점 패널, 저장/불러오기 버튼.
- `SaveFile` — `Application.persistentDataPath/save.json` 읽기·쓰기.

데이터 흐름: 입력 → `BuildController` → 코어 서비스 → 코어 이벤트 → 뷰 갱신. 뷰는 코어를 읽기만 하고, 코어는 뷰를 모른다.

## 5. 오류 처리

- 설치 실패(잔액 부족, 잠긴 칸, 점유된 칸): HUD에 1초 토스트로 사유 표시. 상태 변화 없음.
- 저장 파일 손상: 불러오기 실패 시 새 게임으로 시작하고 토스트로 알림.
- 저장 파일에 버전 필드를 두고, 불일치 시 불러오기를 거부한다.

## 6. 테스트

Unity Test Framework EditMode (NUnit), `Assets/Tests/Core/`.

- 그리드: 잠긴 칸 설치 거부, 점유 칸 설치 거부, 해금 후 설치 허용.
- 이동: 1초 후 1칸 전진, 코너 방향 전환, 앞 칸 점유 시 대기, 고속 레일 2배.
- 배송·소실: 출고구 도착 시 잔액 증가, 레일 끝에서 소실 이벤트.
- 분배기: 연속 2개 택배가 좌·우로 번갈아 나감.
- 경제: 설치비 차감, 잔액 부족 시 실패, 해체 시 10% 차감, 해체 비용 부족 시 실패.
- 해금: 구매 후 영역 확장, 확장 2는 확장 1 이전에 구매 불가.
- 저장: 상태 → JSON → 상태 왕복 후 동일.

Unity 레이어는 수동 플레이 테스트로 확인한다.

## 7. 2차 범위 (이번 구현 제외)

- 택배 종류 `Fragile`, `Large` 와 종류별 전용 출고구.
- 분류기 부품: 종류에 따라 출구를 선택.
- 공장 여러 개와 공장 간 전환 화면.

## 8. 환경

- 이 Mac에는 Unity Hub와 .NET SDK가 아직 없다. 구현 전 `brew install --cask unity-hub dotnet-sdk` 로 설치하고 Unity Hub에서 Unity 6 LTS를 받는다.
- 메모리 8GB이므로 2D URP 템플릿 사용, 에디터 외 무거운 앱은 동시에 띄우지 않는다.
- `.gitignore`는 Unity 표준 템플릿을 사용한다 (`Library/`, `Temp/`, `Logs/`, `UserSettings/` 제외).
