# Parcel Factory — 설계 문서

작성일: 2026-10-15 · 개정 2026-10-16 (9절)
상태: 1차 범위 승인됨, 9절 개정안 검토 중

## 1. 개요

2D 공장 부지에 택배 레일을 설치해 입고된 택배를 출고 트럭까지 운반하는 실시간 경영 게임.
플레이어는 돈을 벌어 새 부품과 부지를 해금하고, 레일 배치를 바꿔 처리량을 늘린다.

- 플랫폼: PC (마우스 + 키보드)
- 엔진: Unity 6.3 LTS (6000.3.x), C#, URP 3D. 9.4절 참고: 2D 격자 게임플레이를 3D 로우폴리로 렌더링한다.
- 진행: 실시간, 일시정지와 배속 가능
- 1차 범위: 공장 1개

## 2. 핵심 루프

1. 입고구에서 일정 주기로 택배가 생성된다.
2. 택배는 레일을 따라 이동한다.
3. 출고구(트럭)에 도착하면 판매되어 잔액이 늘어난다.
4. 레일이 끊긴 곳에서 떨어지면 택배는 소실된다 (수익 0, 추가 손실 없음).
5. 플레이어는 잔액으로 부품을 설치하고, 해금 상점에서 새 부품·부지를 산다.

## 3. 규칙

### 3.1 그리드
- 크기 12×12. 원점 (0,0)은 좌측 하단이며 y는 위로 증가한다. 초기 해금 영역은 x, y 모두 0 이상 6 미만인 6×6.
- 셀 상태: `Empty`, `Conveyor(dir)`, `FastConveyor(dir)`, `Splitter(dir)`, `Inlet`, `Outlet`, `Locked`. (이후 추가: `Table`·`Scanner`·`ReturnDock`은 9절, `Pallet`은 10.2)
- 부품이 있는 셀은 `Demolishing` 플래그와 남은 시간을 가질 수 있다 (3.3 참고).
- 입고구는 (0,2)에 고정 배치. 출고구·반품구는 **10.1에 따라 동쪽 벽 트럭 도크 (11,2)·(11,4)**로 옮겼고, 옛 자리 (5,2)·(5,4)에는 시작 팔레트(10.2)가 놓인다. 도크는 부지를 확장해도 위치가 바뀌지 않으며, 잠긴 구역에 있어도 처음부터 존재하고 플레이어가 철거할 수 없다.
- 방향: `North`, `East`, `South`, `West` 4방향.

### 3.2 부품

| 부품 | 설치비 | 동작 | 초기 해금 |
|---|---|---|---|
| 레일 (방향별) | 10 | 방향으로 택배를 전진시킴 | 동쪽만 |
| 고속 레일 (방향별) | 25 | 레일의 2배 속도 | 아니오 |
| 분배기 | 60 | 들어온 택배를 분배기 방향 기준 좌·우 출구로 번갈아 보냄. 들어온 방향의 정반대로는 절대 보내지 않음(그 경우 다른 출구 사용) | 아니오 |

- 레일과 고속 레일은 **방향마다 별도 도구**다. 툴바에 "레일 →", "레일 ↓" 처럼 방향별 버튼이 있고, 각 방향은 상점에서 따로 해금한다. 회전 키는 없다.
- 코너는 별도 부품이 없다. 동쪽으로 향하는 레일이 남쪽으로 향하는 레일로 이어지면 택배가 그대로 방향을 바꾼다.
- 레일 한 칸에는 택배가 최대 1개. 다음 칸이 점유되어 있으면 현재 칸 끝에서 대기한다.
- 레일이 가리키는 다음 칸이 레일·분배기·출고구가 아니면 택배는 소실된다.

### 3.3 경제
- 시작 잔액: 100.
- 택배 1개 배송: 정상 출고 +30, 불량 반품 +10 (2026-10-20 개정: 9.3 표 참고. 설치비·해금비와의 간격을 줄이기 위해 15/5에서 올림).
- 설치: 잔액에서 설치비 차감. 잔액 부족 시 설치 불가.
- 해체: 우클릭으로 시작하면 **2초**가 걸린다. 완료 시 설치비의 **80%를 환불**한다. 추가 비용은 없다.
- 해체 중인 칸은 새 택배를 받지 않는다. 이미 올라가 있던 택배는 계속 이동하며, 완료 시점까지 남아 있으면 소실된다.
- 해체는 취소할 수 없다. 일시정지 중에는 해체 타이머도 멈춘다.

### 3.4 해금 상점

| 항목 | 가격 | 효과 |
|---|---|---|
| 부지 확장 1 | 200 | 해금 영역을 9×9로 확장 |
| 부지 확장 2 | 500 | 해금 영역을 12×12로 확장 (확장 1 이후) |
| 레일 남/서/북 | 각 50 | 해당 방향 레일 도구 추가 (동쪽은 시작부터 보유) |
| 고속 레일 동/남/서/북 | 각 100 | 해당 방향 고속 레일 도구 추가 |
| 분배기 | 300 | 툴바에 분배기 추가 |

해금 항목은 총 10개. 각 항목은 한 번만 구매할 수 있다.

### 3.5 시간
- 시뮬레이션 틱: 고정 20Hz (0.05초).
- 속도: 일시정지 / 1x / 2x. 일시정지 중에도 설치·해체는 가능하다.
- 입고 주기: 처음 8초에 1개. 성공 배송(출고 +15, 반품 +5) 5건마다 0.5초씩 빨라져 50건부터 3초에 1개(최소). (2026-10-20 개정: 초반이 너무 빨랐음)
- 레일 이동 속도: 1칸/초. 고속 레일 2칸/초.
- 해체 소요 시간: 2초 (시뮬레이션 시간 기준, 배속 영향 받음).

## 4. 구조

### 4.1 코어 (순수 C#, `Assets/Scripts/Core/`, asmdef `ParcelFactory.Core`)

MonoBehaviour와 UnityEngine 의존이 없다. EditMode 테스트 대상.

- `Direction` — 4방향 enum과 오프셋·회전 유틸.
- `CellType`, `Cell` — 셀 상태와 방향.
- `FactoryGrid` — W×H 셀 배열. `IsUnlocked(x,y)`, `Place`, `Remove`, `Get`.
- `PackageKind` — `Normal` (2차에서 `Fragile`, `Large` 추가 예정).
- `Package` — id, kind, 현재 셀 좌표, 진행도(0~1), 이동 중 방향.
- `Package.EntryHeading` — 현재 셀에 들어온 방향. 렌더링에서 코너를 부드럽게 그리는 데 쓴다.
- `ConveyorSim` — `Tick(dt)`: 모든 택배를 전진시키고 점유·배송·소실을 처리. 이벤트: `PackageDelivered`, `PackageLost`.
- `Spawner` — 입고 주기마다 입고구에 택배 생성. 입고구 앞 칸이 점유 중이면 건너뛴다.
- `Economy` — `Money`, `TrySpend(amount)`, `Earn(amount)`.
- `BuildService` — 설치 규칙 검증 후 `FactoryGrid`와 `Economy`를 갱신. 해체 시작(`BeginDemolish`)과 매 틱 타이머 진행(`TickDemolitions`), 완료 시 80% 환불 처리.
- `Toolbar` 상태 — 보유한 도구 목록 (부품 종류 + 방향). `UnlockService`가 구매 시 추가한다.
- `UnlockCatalog`, `UnlockService` — 해금 항목 정의와 구매 처리. 부지 확장은 `FactoryGrid.UnlockRegion`을 호출.
- `GameState` — 위 상태를 담는 직렬화 DTO. `SaveSerializer`가 JSON으로 변환·복원.
- 2차 분류 기능의 확장 지점은 `PackageKind` enum이다. 1차에서 출고구는 모든 종류를 받는다.

### 4.2 Unity 레이어 (`Assets/Scripts/Game/`, asmdef `ParcelFactory.Game`)

- `GameLoop` — `FixedUpdate` 대신 자체 누적기로 20Hz 틱 호출. 속도 배율과 일시정지 보유.
- `GridView` — Tilemap 2개(바닥, 부품). 잠긴 셀은 어두운 타일. 레일 타일은 방향별 스프라이트.
- `PackageView` — 오브젝트 풀. 코어의 셀 좌표 + 진행도를 월드 좌표로 보간.
- `BuildController` — 입력 처리. 툴바에서 방향별 도구 선택, 호버 고스트, 좌클릭 설치, 우클릭 해체 시작(확인 팝업에 환불액과 소요 시간 표시). 해체 중인 셀은 진행 바를 띄운다.
- `HudView` (IMGUI, `OnGUI`) — 잔액, 속도 버튼, 툴바, 해금 상점 패널, 저장/불러오기 버튼, 토스트, 해체 확인 팝업과 진행 바. 씬 편집 없이 코드만으로 구성하기 위해 1차는 IMGUI를 쓴다.
- `SaveFile` — `Application.persistentDataPath/save.json` 읽기·쓰기.

데이터 흐름: 입력 → `BuildController` → 코어 서비스 → 코어 이벤트 → 뷰 갱신. 뷰는 코어를 읽기만 하고, 코어는 뷰를 모른다.

## 5. 오류 처리

- 설치 실패(잔액 부족, 잠긴 칸, 점유된 칸): HUD에 1초 토스트로 사유 표시. 상태 변화 없음.
- 저장 파일 손상 또는 없음: 불러오기 실패 시 현재 세션을 유지하고 토스트로 사유를 알림.
- 저장 실패(IO 오류): 임시 파일에 쓴 뒤 교체하며, 실패 시 기존 파일을 유지하고 토스트로 알림.
- 저장 파일에 버전 필드를 두고, 불일치 시 불러오기를 거부한다.

## 9. 개정 (2026-10-16): 작업자 중심 플레이, 검사, 등각 픽셀아트

참고: Steam 〈Parcel Simulator〉의 루프(입고 → 라벨 검사 → 분류 → 출고, 장비 구매로 자동화)를 2D 정면 3/4 시점 픽셀아트로 옮긴다. 아래 항목은 1차 범위에 **추가**되며, 3~6절과 충돌하는 부분은 이 절이 우선한다. 화면 시안: https://claude.ai/artifact/M5jkC6DBgZkEn1ccq5v8PP

### 9.1 플랫폼과 조작
- PC(마우스+키보드)와 모바일(터치, **가로** 고정) 둘 다 지원한다.
- 플레이어는 공장 안을 걸어 다니는 **작업자**를 직접 조종한다. 설치·해체·집기·놓기·검사는 모두 작업자가 **바라보는 칸**에 대해 수행한다. 클릭으로 아무 칸이나 설치하는 방식은 폐기한다.
- PC: WASD/방향키 이동(상하좌우), E = 상호작용(집기/놓기/설치/검사), X = 해체, 숫자키 또는 클릭으로 도구 선택.
- 모바일: 왼쪽 하단 D-패드(상하좌우 십자), 오른쪽 하단 큰 상호작용 버튼과 해체 버튼, 오른쪽 상단 도구함 목록, 상점은 상단 바 버튼. 터치 타깃 44px 이상.
- ~~작업자는 빈 바닥 칸만 걸을 수 있다.~~ → **9.7로 대체(2026-10-16 저녁 개정)**: 작업자는 격자에 묶이지 않고 부드럽게 걸으며, 레일과 도크 위는 지나갈 수 있다.

### 9.2 수작업 운반
- 작업자는 택배를 **1개** 들 수 있다. 바라보는 칸(입고구, 레일, 검사대 등 트랙)에 택배가 있으면 집고, 들고 있는 상태에서 빈 트랙 칸을 바라보고 놓으면 그 칸의 방향으로 다시 흐른다.
- 들고 있는 택배를 출고구·반품구에 직접 놓으면 그 자리에서 배송 판정(9.3)이 이뤄진다. 초반에는 레일 없이 손으로 나르는 플레이가 가능해야 한다.
- 택배를 들고 있는 동안 부품 설치는 불가.

### 9.3 검사와 분류
- 택배는 생성 시 30% 확률로 **불량**(표기 무게와 실측이 다름)이다. 겉모습으로는 구분되지 않는다.
- 새 부품 **검사대**(설치비 40, 시작부터 보유, 방향 있음): 택배가 올라오면 검사 전까지 멈춘다. 작업자가 검사대를 바라보고 상호작용하면 라벨 카드(목적지, 표기 무게, 배송 방법, 저울 실측)가 뜨고 **승인/거부**를 고른다. 판정 후 택배는 `inspected`, `rejected` 상태를 갖고 검사대 방향으로 계속 흐른다.
- 해금 항목 **자동 검사기**(해금 600, **부지 확장 2(12×12) 이후**에만 구매 가능 — 2026-10-20 개정, 11.10; 설치비 120, 4방향): 레일처럼 흐르면서 진입(또는 작업자가 내려놓는) 즉시 정확히 판정한다. 1차에서는 오판 없음. 이미 사람이 판정한 택배는 다시 판정하지 않는다.
- 새 고정 도크 **반품구**: (5,4)에 고정. 출고구처럼 택배를 받는다.
- 배송 판정(출고구 / 반품구):

| 택배 상태 | 출고구 | 반품구 |
|---|---|---|
| 검사 안 함 | −10 | −5 |
| 승인·정상 | **+30** | −5 |
| 승인·불량 | −30 | −5 |
| 거부·불량 | −10 | **+10** |
| 거부·정상 | −10 | −5 |

### 9.7 작업자 자유 이동 (2026-10-16 저녁 개정, 9.1 다섯째 항목을 대체)
- 작업자 위치는 **연속 좌표**(칸 단위 float, 칸 중심이 정수)다. 입력은 누르고 있는 동안 계속 적용되며 8방향(대각 이동 시 속도 정규화). 속도 3.4칸/초, 충돌 반지름 0.28칸.
- 걸을 수 있는 곳: 해금된 n×n 부지 안의 빈 칸, **레일·고속 레일·입고구·출고구·반품구 위**. 막는 것: 검사대, 분배기, 자동 검사기, 미해금 칸, 부지 경계. 레일 위에 서 있어도 택배 흐름에는 영향이 없고 작업자가 벨트에 실려 가지도 않는다.
- 충돌은 축별로 따로 처리한다(x 이동 → 막히면 취소, y 이동 → 막히면 취소). 그래서 벽을 따라 미끄러진다.
- 바라보는 방향은 마지막 이동 벡터의 지배 축으로 정한다(|vx| ≥ |vy| → 동/서, 아니면 북/남). 바라보는 칸 = `round(위치 + 방향 × 0.8)`. 상호작용·설치·해체·검사는 모두 이 칸에 대해 수행한다.
- 설치 제한: 막는 부품(검사대·분배기·자동 검사기)은 작업자의 충돌원과 겹치는 칸에 놓을 수 없다(`InteractResult.Standing`). 레일은 작업자가 서 있는 칸에도 놓을 수 있다.
- 모바일: D-패드는 **누르고 있는 동안** 이동(탭 1회 = 1칸 방식 폐기).
- 코어 변경: `Worker.X/Y`를 float로, `WorkerService.Move(vx, vy, dt)`가 `TryMove(dir)`를 대체, `FacingTile()`은 위의 규칙, `GameState` v3(작업자 좌표 float; v2 저장은 칸 중심으로 변환해 읽는다). 이동 중에는 `CancelInspection()`.

## 10. 개정 (2026-10-20): 트럭 도크와 팔레트 — 수작업 출고, 확장하면 자동화

사용자 결정: 출고·반품은 "자동으로 연결"되지 않는다. 파란/빨간 칸은 택배가 **쌓이는 팔레트**이고, 작업자가 거기서 택배를 집어 **트럭까지** 직접 나른다. 부지를 동쪽 벽까지 넓히면 레일을 트럭 도크에 바로 붙여 자동화할 수 있다. 3.1·9.5·9.7과 충돌하는 부분은 이 절이 우선한다.

### 10.1 트럭 도크 (판정 지점)
- `Outlet`은 (11,2), `ReturnDock`은 (11,4)로 옮긴다. 동쪽 벽 출입구 바로 안쪽 칸이며 차량이 그 밖에 후진 주차되어 있다. 해금 여부와 무관하게 처음부터 존재하고 철거할 수 없다. 입고구는 (0,2) 그대로.
- 레일이 닿아 흘러 들어오거나 작업자가 손으로 놓으면 **그 자리에서** 9.3 판정표대로 판정한다. 판정은 트럭 도크에서만 일어난다.
- 12칸까지 해금하면 (10,2)·(10,4)에 동향 레일을 두어 트럭으로 자동 투입할 수 있다. 그 전에는 (6..10, ·)이 잠겨 있어 레일을 못 놓으므로 손으로 날라야 한다.

### 10.2 팔레트 (적재대)
- 새 부품 `Pallet`: 설치비 20, 시작부터 보유, 해체 2초·환불 80%. 방향 대신 **종류**가 있다: `Blue`(출고 대기)·`Red`(반품 대기). 색은 안내용이며 판정과 무관하다. 도구 표현은 기존 `Tool(Type, Direction)`을 재사용해 `East = Blue`, `West = Red`로 매핑하고, R(또는 슬롯 재탭)로 종류를 순환한다.
- 시작 배치: (5,2) Blue, (5,4) Red가 미리 설치되어 있다(옛 출고구·반품구 자리). 플레이어가 해체하거나 옮길 수 있다.
- 용량 6. 레일에서 흘러 들어온 택배는 흐름에서 빠져 팔레트 더미에 쌓인다(검사 상태 유지). 가득 차면 앞 레일의 택배는 대기한다. 팔레트에서 레일로 자동 유출은 없다.
- 작업자가 팔레트를 바라보고 E → 맨 위 택배를 집는다. 들고 있는 택배를 팔레트에 놓을 수도 있다(용량 내). 팔레트 위에 택배가 있으면 해체할 수 없다(`Occupied`).
- 팔레트는 걸어서 지나갈 수 없다.

### 10.3 걷기와 설치 범위
- 건물 안 12×12는 **전부 걸어 다닐 수 있다**(잠긴 칸 포함; 바닥일 뿐이다). 9.7의 "부지 경계"는 격자 경계로 바뀐다. 막는 것은 검사대·분배기·자동 검사기·팔레트뿐이다.
- 설치는 해금된 칸에만 가능하다(변경 없음). 트럭 도크 칸은 항상 상호작용(놓기) 가능하다.

### 10.4 HUD·월드

## 11. 개정 (2026-10-20): 근무 시간, 점심시간, 작업자 스태미나

### 11.1 시계
- 게임 시간은 **1게임분 = 1실제초**(1x 기준, 배속 2x면 2게임분). 하루는 09:00부터 18:00까지 9게임시간 = 9실제분.

- 단계(`DayPhase`): `Working`(09:00–11:59, 13:00–17:59), `Lunch`(12:00–12:59), `Closed`(18:00 이후, 다음 날 09:00까지 하루 요약이 떠 있는 동안).
- 점심시간: 입고가 멈춘다(입고 타이머도 멈춤). 레일·해체 등 시뮬레이션은 계속 돈다. 작업자는 자유롭게 움직일 수 있지만 스태미나가 빠르게 회복된다(11.3). HUD에 "점심시간" 배너.
- 18:00 퇴근: 입고가 멈추고 시뮬레이션이 멈춘다(일시정지와 같음). **하루 요약** 패널: 날짜, 배송 수, 소실 수, 잔액 변화(그날 시작 잔액 대비), 검사 수. "다음 날" 버튼을 누르면 다음 날 09:00으로 넘어가고 스태미나가 가득 찬다. 레일 위·팔레트 위 택배는 그대로 남는다.
- 저장 v5: 날짜, 하루 중 분, 그날 시작 잔액, 스태미나.

### 11.3 스태미나

### 11.5 체력 규칙 개정과 EXP 상태창 (2026-10-20)
- 체력 소모는 달리기에만 있다: 달리기 초당 3.0, 들고 달리기 초당 5.5(`RunDrain`, `RunCarryDrain`). 걷기·집기·놓기·설치는 소모 없음. 회복은 걷든 서든 초당 0.8, 점심 초당 20. 체력 0이면 집을 수 없고(`Exhausted`), 10 미만이면 달릴 수 없다.
- **EXP**: 정상 출고 +10, 불량 반품 +8, 검사 수행(검사대 승인/거부, 자동 검사기 판정) +2. 잔액과 별개의 누적치이며 강화에 쓴다. HUD 좌상단 패널에 "EXP n" 표시.
- **상태창**(상점과 별개, 상단 바 "상태 C" 버튼 / C 키 / 터치 버튼): 작업자 능력치와 강화.

| 능력치 | 효과(레벨당) | 최대 레벨 | 비용(EXP, 레벨 n으로 올릴 때) |
|---|---|---|---|
| 체력 | 최대 체력 +20 (기본 100) | 5 | 40 × n |
| 이동 속도 | 걷기·달리기 속도 +8% | 5 | 50 × n |
| 회복력 | 체력 회복 +50% (서 있을 때·걸을 때) | 3 | 40 × n |

- 강화는 즉시 적용되고 되돌릴 수 없다. 체력 강화 시 현재 체력도 같은 양만큼 오른다.
- 코어: `Progression { Exp, Level(Stat), MaxLevel(Stat), Cost(Stat), TryUpgrade(Stat) → UpgradeResult { Ok, MaxLevel, NotEnoughExp }, MaxStamina, SpeedMultiplier, RegenMultiplier; event ExpChanged, Upgraded }`, `GameSession.Progression`; `WorkerService`가 `MaxStamina/SpeedMultiplier/RegenMultiplier`를 Progression에서 읽는다. EXP 적립은 `ConveyorSim.PackageDelivered`(성공 판정)와 `NoteInspected`에서. 저장 v6(Exp, 레벨 3개).
- 하루 요약에 "획득 EXP"를 추가한다.

### 11.6 분배기 규칙 개정 (2026-10-20)
- 분배기는 **연결된 출구**로 번갈아 보낸다. 출구 후보 = 분배기 칸의 4방향 이웃 중 (a) 택배가 들어온 방향의 정반대가 아니고 (b) 트랙(레일·고속·검사대·자동 검사기·분배기)이거나 팔레트·트럭 도크인 칸. 후보 순서는 분배기 방향 기준 왼쪽 → 앞 → 오른쪽 → 뒤(뒤는 옆에서 들어온 경우에만 후보가 된다)이고, 입고구는 후보에서 제외한다, 라운드로빈 인덱스를 돌린다(후보 수가 바뀌어도 인덱스는 나머지 연산).
- 후보가 하나면 항상 그쪽, 후보가 없으면 분배기 방향으로 내보낸다(그 앞이 비어 있으면 기존대로 소실).
- 뷰: 분배기 허브(보라색) 위에 연결된 출구마다 화살표를 그린다. 이웃 칸이 바뀌면 분배기 뷰도 다시 그린다. 방향 설정은 후보 순서와 모델 방향에만 영향을 준다.

### 11.7 분배기 = 분류기 (2026-10-20, 11.6을 대체)
- 분배기는 번갈아 보내지 않고 **검사 결과로 분류**한다. 파란 출구 = 승인(정상 판정) 택배, 빨간 출구 = 거부 택배. 검사하지 않은 택배는 파란 출구로 간다.
- 파란 출구 = 분배기의 `Direction`(R / 슬롯 재탭으로 4방향 순환; 분배기 해금 시 4방향 모두 보유). 빨간 출구 = 파란 출구를 제외한 **연결된 출구** 중 첫 번째(순서: 파란 기준 오른쪽 → 왼쪽 → 뒤). 연결된 출구 판정은 11.6과 같다(레일·검사대·자동 검사기·분배기·팔레트·트럭 도크, 입고구 제외, 들어온 방향 제외).
- 해당 색의 출구가 없으면: 빨강이 없으면 거부 택배도 파란 출구로. 파란 출구가 연결돼 있지 않으면 승인·미검사 택배는 `Direction`으로 직진(앞이 비어 있으면 소실)하고, 거부 택배는 빨간 출구가 있으면 여전히 그쪽으로 간다.
- 뷰: 보라 허브 위에 파란 화살표(파란 출구)와 빨간 화살표(빨간 출구). 이웃이 바뀌면 다시 그린다. 설치 프롬프트 "분배기 설치 (파랑 →) · ₩60".
- `SplitterIndex`는 더 이상 쓰지 않는다(저장 필드는 무시).

### 11.8 방향 입력 방식 통일, 설치 후 재설정, 미니 상태바 (2026-10-20)
**방향 입력**: 방향은 더 이상 순환하지 않는다. **R을 누른 뒤 화살표(또는 WASD)로 방향을 직접 입력**한다. 설정이 둘인 부품은 R 다음에 **1 또는 2**로 어느 설정인지 고른 뒤 화살표를 누른다.
- 도구(핫바)에서: 레일·고속·검사대·자동 검사기 = R → 화살표. 분배기 = R → 1(파랑) 또는 2(빨강) → 화살표. 팔레트 = R → 1(파랑) 또는 2(빨강) (화살표 없음).
- **설치된 부품 재설정**: 그 부품을 바라보고 R을 누르면 같은 방식으로 **그 자리에서** 바꾼다(비용 없음, 철거 불필요). 레일 방향을 바꾸면 그 칸 위에 있는 택배의 진행 방향도 새 방향으로 바뀐다. 입고구·트럭 도크는 바꿀 수 없다.
- 분배기의 빨간 출구는 이제 **명시 설정**이다(`RedDirection`). 설정하지 않았으면 11.7의 자동 규칙(파란 기준 오른쪽 → 왼쪽 → 뒤 중 연결된 것). 파란·빨간 출구가 같은 방향이면 빨간 설정을 무시하고 자동 규칙으로 돌아간다.
- 입력 상태는 HUD에 배너로 보인다: "방향 입력: ← ↑ → ↓ (Esc 취소)", "1 파랑 / 2 빨강 선택". Esc나 다른 키(E, X, 숫자 3~6)로 취소. 모바일: R 버튼 → D-패드 방향 / 핫바 1·2 탭.
- 입력 중에는 화살표·WASD가 이동이 아니라 방향 입력으로 쓰이고, 한 번 입력하면 모드가 끝난다.

**미니 상태바**: 설치된 모든 부품 위에 작은 상태 표시(반투명 검은 알약, 11px)를 띄운다. 내용: 레일/고속 "→", 검사대 "검사 대기 n" 또는 "검사대", 자동 검사기 "자동 →", 분배기 "파 → · 빨 ↓", 팔레트 "파랑 3/6". 작업자가 바라보는 부품의 상태바는 밝게 강조되고 "R 설정" 힌트가 붙는다. 상태바는 월드 위치를 매 프레임 화면에 투영해 그린다(택배 팝업과 같은 방식). 상태가 바뀌면 즉시 갱신.

- 코어: `Cell.RedDirection`(Direction?, 분배기만), `BuildService.SetDirection(x, y, dir)`(레일·고속·검사대·자동 검사기·분배기 파랑; `CellChanged` 발생; 그 칸 택배 Heading 갱신), `SetSplitterRed(x, y, Direction?)`, `SetPalletKind(x, y, kind)`; 결과 `ReconfigureResult { Ok, NotConfigurable, Invalid, NotOwned }` (`NotOwned` = 레일·고속 레일을 보유하지 않은 방향으로 바꾸려 할 때). `ConveyorSim.SplitterRoutes`가 `RedDirection`을 우선한다. 저장: `CellState.RedDirection`(선택 필드, 버전 유지 6).
- `Toolbar`: 방향별 보유는 유지(해금 체계 그대로). 도구 방향 입력 시 보유하지 않은 방향이면 토스트 "해금되지 않은 방향입니다"(분배기·검사대·자동 검사기는 4방향 모두 보유).

### 11.9 Esc 우선순위와 설치 미리보기 (2026-10-20)
- **Esc 우선순위**: ① 설정 모드 취소 → ② 열린 패널 닫기(하루 요약 제외) → ③ 손에 든 도구 내려놓기(빈손, Q와 같음). 즉 아무것도 열려 있지 않을 때 Esc는 핫바 선택을 해제한다. 설정 모드를 취소해도 도구 선택은 유지된다(다시 Esc를 누르면 해제).
- **설치 미리보기(고스트)**: 도구를 들고 있으면 바라보는 칸에 그 부품의 반투명 미리보기를 그린다. 방향·종류(파랑/빨강)·분배기 출구 화살표까지 실제 모양 그대로. 설치 가능(`Preview == Placed`)이면 초록 틴트, 불가(잠김·점유·잔액 부족·서 있는 자리)면 빨간 틴트. 바라보는 칸이 바뀌거나 도구가 바뀌면 즉시 갱신. 설정 모드에서 방향을 입력하는 동안에도 보인다.

### 11.11 체력 회복 상한과 점심 휴식 (2026-10-20)
- **평소 회복 상한 80%**: 근무 중 회복(서 있든 걷든 초당 0.8 × 회복력)은 최대 체력의 **80%까지만** 채운다. 80% 이상이면 회복하지 않는다(소모는 그대로). 설계 기준: 점심 전까지 최대 50% 정도 소진된다고 보고, 평소 회복만으로는 완전 회복이 안 되게 한다.
- **점심 휴식**: 점심시간(12:00–12:59)에 작업자가 **가만히 서 있는 동안**(그 프레임에 이동하지 않음) 초당 20씩 **100%까지** 회복한다. 점심시간에 움직이면 그 프레임은 평소 규칙(80% 상한)이다. 즉 점심에 쉬어야 만땅이 된다.
- 체력 강화(11.5)로 최대치가 오르면 상한도 그 80%다. 하루 시작은 100%.
- 코어: `WorkerService.RegenCap = 0.8f`; `Rest(dt, phase)`에 "이번 프레임 이동 여부"가 다시 필요하므로 `Move`가 세우는 `movedThisFrame` 플래그를 `Rest`가 소비한다(점심 판단에만 사용). HUD 체력 바에 80% 지점에 얇은 눈금을 긋는다.

### 11.12 브릿지 레일 (2026-10-20)
- 새 부품 **브릿지**(`CellType.Bridge`): 레일이 서로 **교차**할 수 있게 하는 입체 교차로. 한 칸에 두 개의 독립된 차선이 있다.
  - **윗길**: 브릿지의 `Direction`으로 흐르는 고가 벨트. 윗길과 **평행하게** 들어온 택배(앞/뒤에서 진입)가 탄다. 진행 방향은 레일처럼 `Direction`.
  - **아랫길**: `Direction`과 **수직인** 축의 바닥 벨트. 옆에서 들어온 택배는 들어온 방향 그대로 **직진**해 반대쪽으로 나간다(좌→우, 우→좌 모두).
  - 두 차선은 점유를 따로 센다(`Cell.OccupantId`는 윗길, `Cell.LowerOccupantId`는 아랫길). 대기·소실 규칙은 레일과 같다.
- 설치비 40, 해금 "브릿지" 200(부지 확장 1 필요), 4방향 보유. 핫바 순서: 레일, 고속, **브릿지**, 팔레트, 검사대, 분배기, 자동 검사기 → 최대 7칸(키 1~7). R → 화살표로 윗길 방향. 재설정 가능.
- 걷기: 레일처럼 지나갈 수 있다. 팔레트·도크·검사대로의 연결 규칙은 레일과 같다(브릿지는 `IsTrack`).
- 뷰: 바닥 벨트(수직 축, 양방향이라 화살표 없음) + 기둥 4개 + 높이 0.9의 고가 벨트(`Direction` 축, 흐르는 화살표). 택배 높이: 윗길 1.3, 아랫길 0.4. 미니 상태바 "브릿지 ↑"(윗길 방향).
- 분배기 출구·스캐너 등 다른 부품에서 브릿지로 들어오는 것도 같은 규칙(평행이면 윗길, 수직이면 아랫길).
- 저장: 셀 타입 추가, `LowerOccupantId`는 저장하지 않고 복원 시 택배 위치·진행 방향에서 다시 계산한다(택배 상태에 `Lane` 필드 추가: Upper/Lower). 버전 6 유지(필드 추가만).

## 12. 개정 (2026-10-21): 시작 화면과 UI 품질 — 시안과 같은 수준

빌드를 실행하면 바로 게임이 돌아가고, HUD가 사각 상자와 얇은 글씨로 그려져 3D 시안(`docs/design/prototype/parcel-factory-3d.html`, `docs/design/3d-mockup-*.png`)보다 조잡했다. 원인은 세 가지였다. 폰트 파일이 가변 폰트라 유니티가 기본 굵기 100(Thin)으로만 그렸고, `Image`에 스프라이트가 없어 모서리가 직각이었고, 아이콘·키캡·알약 같은 시안의 부품이 없었다. 이 절이 UI의 기준이다. 시안과 다르면 시안이 맞다.

### 12.1 시작 화면

- 실행하면 시작 화면이 먼저 뜬다. 뒤에는 3D 공장이 그대로 렌더되고, 왼쪽이 짙고 오른쪽으로 옅어지는 어두운 그라데이션이 덮는다. 시작 화면이 떠 있는 동안 시뮬레이션·시계·입력은 멈추고 HUD는 숨긴다.
- 왼쪽 세로 열(왼쪽 여백 96, 세로 가운데): 앰버 둥근 타일 안의 상자 아이콘(56) → `PARCEL FACTORY`(Sora Bold 44, 자간 넓게) → `택배 공장 운영 시뮬레이션`(Noto Medium 16, muted) → 메뉴 버튼 세로 4개(폭 300, 높이 52, 반경 12, 간격 10).
- 메뉴: **이어하기**(저장 파일이 있을 때만, 버튼 안 아래줄에 `N일차 · ₩금액`), **새 게임**, **조작법**, **종료**(데스크톱만, 모바일·에디터 테스트에서는 숨김). 첫 버튼이 기본 선택이며 앰버로 채운다. 나머지는 패널색 + 1px 선.
- 키보드: ↑/↓(W/S)로 선택 이동, Enter·Space·E로 실행. 선택된 버튼은 앰버 2px 테두리. 마우스 hover도 선택을 옮긴다. 조작법은 시작 화면 위에 조작 카드(인게임 조작 패널과 같은 내용)를 띄우고 Esc나 닫기로 돌아온다.

- 인게임 상단 오른쪽의 `새 게임` 버튼은 `메뉴`로 바뀐다. 누르면 일시정지 상태로 시작 화면으로 돌아간다(진행 중 세션은 유지, 이어하기 대신 **계속하기**가 첫 버튼). 새 게임은 시작 화면에서만 시작한다.

## 13. 개정 (2026-10-21): 환경설정 — 소리와 화면

게임에 소리가 없었다. 음악과 공장 배경소리를 재생할 자리를 만들고, 소리 크기와 화면 해상도·창 모드·전체 화면을 고르는 설정 카드를 만든다.

### 13.1 소리

- 음원은 사용자가 직접 고른다(무료 라이선스만). 이번 단계는 기능만 만들고 음원 파일은 넣지 않는다.
- 음악은 `Assets/Resources/Audio/music-shift`, 배경소리는 `Assets/Resources/Audio/ambient-factory`(확장자 무관: wav·ogg·mp3). 파일이 없으면 조용히 건너뛰고, 설정 카드의 해당 슬라이더 아래에 `음원 없음 · Resources/Audio에 넣으면 재생됩니다`를 보인다.
- `AudioDirector`(Game 레이어)가 AudioSource 두 개로 둘 다 반복 재생한다. 실제 볼륨 = 설정값²(0~1, 귀에 고르게 들리도록). 배경소리는 시작 화면·일시정지·하루 요약 중에는 0.5초에 걸쳐 0으로 줄고, 점심시간에는 절반, 근무 중에는 100%. 음악은 항상 재생한다.
- 기본값: 음악 60 · 배경소리 70.

### 13.2 화면 (데스크톱만, 모바일에서는 이 묶음을 숨긴다)

- 단위: 모든 해상도 값은 렌더 **픽셀**이다(`Screen.resolutions`·`currentResolution`·`SetResolution` 모두). Retina macOS에서 창의 포인트 크기는 그 절반이다(실측: 1280×720 창 = 640×360pt). 그래서 고정 창 크기만 두면 Retina에서 창이 너무 작다.
- 화면 모드: `창 모드` / `전체 화면` 두 값. 전체 화면은 `FullScreenMode.FullScreenWindow`(macOS에서 배타적 전체 화면은 지원되지 않는다). 창 모드는 `Windowed`, 창 크기 조절 가능(`resizableWindow: 1`).
- 해상도 후보는 **일반 해상도 표**에서만 고른다(2026-10-21 사용자 요청): 16:9 `1280×720 · 1366×768 · 1600×900 · 1920×1080 · 2560×1440 · 3840×2160`, 16:10 `1280×800 · 1440×900 · 1680×1050 · 1920×1200 · 2560×1600`. `Screen.resolutions`는 쓰지 않는다(Retina에서 3024×1890 같은 값이 섞인다). 오름차순.
  - 전체 화면: 모니터보다 크지 않은 일반 해상도 + 모니터 네이티브 크기 하나(표기 `3024 × 1964 · 네이티브`).
  - 창 모드: 창 상한(폭 ≤ 모니터 95%, 높이 ≤ 모니터 85%) 안의 일반 해상도. Retina에서는 픽셀 기준이라 1280×720 창이 작게 보인다(640×360pt). 기본은 1920×1080, 상한을 넘으면 상한 안의 가장 큰 것.
  - 세그먼트로 모드를 바꾸면 후보를 다시 채우고 가장 가까운 후보로 맞춘다. 창 상한을 넘는 크기에서 창 모드로 바꾸면 기본 창 크기에 맞춘다. 저장된 크기가 일반 해상도가 아니면 카드를 열 때 가장 가까운 일반 해상도를 고르고 적용이 켜진다.
- 적용: 저장된 크기를 모니터 안으로 줄이고, 창 모드면 창 상한 안으로 비율을 지켜 줄인다(짝수). 지금 화면과 같으면 호출하지 않는다. 플레이어 빌드에서 실제로 바꾸면 다음 프레임에 `Player.log`로 `[Settings] apply requested {W}x{H} {모드} -> screen {Screen.width}x{Screen.height} {Screen.fullScreenMode}` 한 줄을 남긴다.
- 화면 값은 `적용`을 눌러야 바뀐다(소리는 즉시 반영). 적용한 값은 다음 실행에도 유지한다. 화면 값이 한 번도 저장되지 않았으면(`pf.resW` 없음) 부팅 때 화면을 건드리지 않고 지금 화면(`Screen.width`·`height`·`fullScreen`)을 설정값으로 쓴다.

### 13.3 설정 카드

- 여는 곳: 시작 화면 메뉴의 **설정**(조작법 위), 인게임 상단 `메뉴` → 설정. 시작 화면 위에 카드로 뜬다(폭 420, §12 카드 스타일).
- 자리: 시작 화면(인게임 메뉴 포함)에서 메뉴 열(제목 포함) 오른쪽 빈 영역의 가로·세로 가운데. 뒤 막은 그대로. 열면 첫 행(음악)이 선택돼 있다.
- 행: `소리` 소제목 → 음악 슬라이더 · 배경소리 슬라이더(트랙 6px 알약, 채움 앰버, 손잡이 원 16, 오른쪽에 값 Sora) → `화면` 소제목 → 화면 모드(두 칸 세그먼트, 선택 칸 앰버) · 해상도(`‹ 1920 × 1080 ›` 스테퍼) → 아래 버튼 `닫기` · `적용`(주 버튼, 화면 값이 바뀌었을 때만 활성).
- 키보드: ↑/↓ 행 이동, ←/→ 값 조절(슬라이더 5씩), Enter(게임패드 A) 적용, Esc(게임패드 B) 닫기. 선택 행은 앰버 테두리. 마우스 드래그·클릭도 된다.
- 저장: `PlayerPrefs`(키 `pf.music`, `pf.ambient`, `pf.fullscreen`, `pf.resW`, `pf.resH`). 소리 값은 자기 키만, 적용은 화면 키 세 개만 쓴다. 슬라이더 드래그 중에는 메모리 값과 실제 볼륨만 바뀌고, 디스크 저장은 손을 뗄 때·카드를 닫을 때·앱 종료/일시정지 때 한다(키보드 ←/→는 누를 때마다). 부팅 시 읽는다. 세이브 파일(`save.json`)과는 별개다.

## 14. 개정 (2026-10-21): 항공 택배와 항공 트럭

부지 확장 2(12×12)를 사면 항공 택배가 들어오기 시작하고, 동쪽 벽에 항공 전용 트럭 두 대가 생긴다.

### 14.1 항공 도크

- 새 칸 종류 `AirOutlet`(항공 출고, **초록** 트럭)과 `AirReturnDock`(항공 반품, **노랑** 트럭). 위치는 동쪽 벽 안쪽 `(11,7)`과 `(11,9)`. 기존 출고 `(11,2)`·반품 `(11,4)`과 같은 모양의 도크·벽 출입구·트럭이다.
- 부지 확장 2를 사는 순간 두 칸이 도크로 바뀌고 트럭이 나타난다(`FactoryGrid.UnlockRegion(12)`에서 만든다. 확장 전에는 그 칸이 잠긴 칸이라 충돌이 없다). 단, v6 저장에서 부지 확장 2 뒤 그 두 칸에 지어 둔 설치물은 불러올 때 철거하고 설치비 전액을 돌려준다. 그 위에 있던 택배는 소실로 센다. 확장 전에는 트럭도 출입구도 없다. 저장 파일을 불러와도 같은 규칙으로 다시 생긴다.
- 도크 동작은 기존 도크와 같다: 레일이 밀어 넣거나 작업자가 들고 와서 E. 해체·설치 불가. 기존 도크처럼 걸어서 지나갈 수 있다(스펙 10.3).
- 기존 입고 트럭도 초록이지만 서쪽 벽에 있어 위치로 구분된다. 항공 트럭 지붕에는 상자와 같은 항공 마크(`mark-air`)를 평평하게 붙인다(2026-10-21 사용자 수정: 떠 있는 표지판 대신).

### 14.2 항공 택배

- 부지 확장 2 이후 새로 들어오는 택배의 25%가 항공 택배다(`Package.Air = true`, 라벨 배송 방법 `항공`). 확장 전에는 만들지 않는다.
- 상자 윗면 가운데에 항공 마크(`Assets/Resources/UI/Icons/mark-air.png`: 파란 둥근 사각 + 흰 비행기 + 흰 테두리, 상자 윗면 폭의 약 55%)를 붙인다. 레일 위·팔레트 더미·손에 든 상태 모두 보인다. 검사 전에도 보인다(겉 라벨이므로).
- 검사 카드의 배송 방법 줄에 `항공`과 비행기 아이콘을 보인다. 미니 상태바·프롬프트는 항공 택배를 들고 있으면 `항공` 꼬리표를 붙인다(예: `항공 출고 +30`).

### 14.3 판정 (스펙 9.3 표를 확장)

- 항공 택배가 항공 도크로 가면 기존 표와 같다: 항공 출고는 출고 규칙(승인·정상 +30 …), 항공 반품은 반품 규칙(거부·불량 +10 …).
- 운송 수단이 틀리면 새 결과 `WrongCarrier` −10, EXP 없음: 항공 택배를 일반 출고·반품 트럭에 넣거나, 일반 택배를 항공 트럭에 넣은 경우. 검사 여부보다 먼저 판정한다.
- 프롬프트와 돈 팝업은 기존처럼 결과 금액을 보인다(틀린 운송 수단이면 `운송 수단 틀림 −10`).

### 14.4 저장

- 저장 버전 v7: 택배에 `Air`(없으면 false). v6 파일도 읽는다. 항공 도크 칸은 저장된 칸 종류로 복원되며, 부지 확장 2를 가진 v6 저장을 읽으면 `UnlockRegion(12)` 규칙으로 도크가 생긴다.

### 14.5 분배기와 자동 검사기의 항공 모드 (2026-10-21 추가 요청)

- 분배기와 자동 검사기에 **모드**가 생긴다: `검사`(기본, 지금 동작) / `항공`. 칸마다 따로 저장한다(`Cell.Mode`).
- 설정: 분배기·검사기 앞에서 **R → 3** 으로 모드를 바꾼다(바로 적용, 무료). 부지 확장 2 전에는 바꿀 수 없고 토스트 `부지 확장 2 이후 사용 가능`. 설정 배너·조작 도움말에 `3 모드` 를 추가한다.
- **분배기 · 항공 모드**(2026-10-21 사용자 수정): 항공 줄에 쓰는 분배기다. 가르는 규칙은 검사 모드와 같다: 1번 출구 = 정상(승인), 2번 출구 = 반품(거부). 다른 점은 색과 이름뿐이다: 1번 **초록**(항공 출고 트럭 색), 2번 **노랑**(항공 반품 트럭 색). 설정은 지금과 같다(R → 1 → 화살표, R → 2 → 화살표). 운송 수단은 가르지 않는다(그건 검사기 항공 모드가 한다).
- **자동 검사기 · 항공 모드**: 지금처럼 자동 검사를 하고, 내보낼 때 항공 택배는 2번 출구(항공 출구)로, 일반 택배는 1번 출구(기존 방향)로 보낸다. 설정은 R → 1 → 화살표(일반 출구), R → 2 → 화살표(항공 출구). 검사 모드에서는 지금처럼 R → 화살표 한 번(출구 하나). 항공 모드로 처음 바꾸면 항공 출구 기본값은 일반 출구의 오른쪽이고, 그 칸이 나갈 수 없는 곳이면 왼쪽.
- 검사기 항공 모드의 출구 규칙: 정해진 출구가 막히면(앞 칸이 차 있거나 받을 수 없으면) 기다린다. 다른 출구로 새지 않는다. 분배기는 지금처럼 받을 수 없는 출구로 보내면 소실된다(두 설비의 실패 방식이 다르다). 검사기가 막혀 기다리면 미니 상태바에서 막힌 출구를 흐리게 보이고, 처음 막힐 때 토스트 `검사기 출구가 막혔습니다`.
- 화살표 색: 분배기 검사 모드는 지금처럼 파랑(승인)·빨강(거부), 분배기 항공 모드는 초록(정상)·노랑(반품). 검사기 항공 모드는 1번 일반 = 흰색, 2번 항공 = 항공 마크 파랑(`#2f86eb`). 설치 미리보기·미니 상태바도 같은 색. 미니 상태바 문구: `분배기 · 항공`(초록/노랑 출구 표시), `검사기 · 항공`.
- 저장 v7에 `Mode`(없으면 검사)와 검사기의 두 번째 출구를 넣는다.
- 이것으로 12×12 자동화가 된다: 검사기(항공 모드)로 항공/일반을 가른 뒤, 일반 줄은 분배기(검사 모드, 파랑/빨강)로, 항공 줄은 분배기(항공 모드, 초록/노랑)로 정상/반품을 갈라 네 트럭으로 보낸다.

## 15. 개정 (2026-10-21): 운송장 부착대

검사와 별개로, 택배에 운송장을 붙이는 단계가 생긴다. 검사대와 운송장 부착대를 둘 다 거쳐야 정상 처리다(사용자 결정).

### 15.1 설비

- 새 설치물 `운송장 부착대`(`CellType.Labeler`, 설치비 ₩20, 처음부터 사용 가능). 핫바 순서는 검사대 다음: 레일 · 고속 레일 · 브릿지 · 팔레트 · 검사대 · **부착대** · 분배기 · 검사기 (키 1~8). 해체 환불 규칙은 다른 설치물과 같다.
- 동작은 검사대와 같은 틀이다: 레일로 들어온 택배 중 **검사됐고 운송장이 없는** 택배는 부착대 위에서 멈춘다. 검사 안 된 택배와 이미 운송장이 있는 택배는 멈추지 않고 지나간다. 작업자가 들고 와서 E로 부착대에 올려놓을 수도 있다. 걸어서 지나갈 수 없다.
- 부착대 앞에서 E: 멈춘 택배가 있으면 운송장 카드를 연다. 검사 안 된 택배를 올려놓으려 하면 토스트 `먼저 검사하세요`.
- 모델: 검사대와 같은 작업대에 운송장 롤(흰 원통)과 작은 프린터를 얹은 모양, 미니 상태바 `부착대`.

### 15.2 운송장 카드 (드래그로 붙이기)

- §12 카드 스타일, 폭 약 600. 왼쪽: 위에서 내려다본 상자(골판지색 둥근 사각, 테이프 줄, 항공이면 모서리에 항공 마크), 상자 중앙에 점선 둥근 사각 **부착 영역**. 오른쪽: 운송장 한 장(흰 종이, 둥근 모서리 6, 그림자). 운송장 종류는 택배에 맞게 하나만 나온다:
  - 승인 → `출고 운송장`(머리띠 파랑), 거부 → `반품 운송장`(머리띠 빨강). 항공 택배면 머리띠 옆에 비행기 배지와 `항공`.
  - 내용: 택배 번호, 목적지(크게), 표기 무게, 바코드 모양 줄.
- 운송장을 마우스나 터치로 끌어 부착 영역에 놓으면 붙는다(운송장 중심이 영역 안). 붙으면 운송장이 영역 중앙에 착 맞춰지고 0.4초 뒤 카드가 닫히며 토스트 `운송장 부착`. 영역 밖에 놓으면 제자리로 돌아간다. 끄는 동안 운송장은 살짝 커지고(1.05배) 영역 테두리가 앰버로 밝아진다.
- 키보드 대체: Enter 또는 E로 바로 붙인다(접근성·테스트용). Esc는 붙이지 않고 닫는다(택배는 부착대에 남는다).

### 15.3 판정과 자동화

- `Package.Waybill`(bool). 운송장이 붙은 상자는 3D에서 윗면 **중앙**에 흰 운송장(머리띠 파랑/빨강, 바코드 줄)이 보인다. 항공 마크(스펙 14.2)는 상자 윗면 **모서리**로 옮긴다(운송장과 겹치지 않게).
- 자동 검사기를 지나는 택배는 검사와 함께 운송장도 자동으로 붙는다.
- 판정 순서(스펙 9.3·14.3 확장): 운송 수단 틀림(−10) → 미검사(기존) → **운송장 없음**: 출고 도크(일반·항공) `NoWaybillToOutlet` −20, 반품 도크(일반·항공) `NoWaybillToReturn` −10, 둘 다 실패·EXP 없음 → 기존 결과.
- 프롬프트는 결과 금액을 보인다(예: `출고 −20 · 운송장 없음`). 미니 상태바와 검사 카드에는 운송장 상태(`운송장 ✓`/`운송장 없음`)를 보인다.
- 저장 v7(스펙 14.4와 같은 버전)에 `Waybill`(없으면 false). 이전 저장 파일의 택배는 운송장이 없는 상태로 읽힌다.

## 16. 개정 (2026-10-21): 미검사 감점 상향, 부지마다 입고구 추가

### 16.1 미검사 감점

- 미검사 택배를 트럭에 넣으면 운송장 없음과 같은 금액이다: 출고 도크(일반·항공) `UninspectedToOutlet` **−20**(이전 −10), 반품 도크(일반·항공) `UninspectedToReturn` **−10**(이전 −5). 판정 순서(운송 수단 → 미검사 → 운송장 → 기존)는 그대로다. 조작 도움말·프롬프트 금액도 바꾼다.

### 16.2 부지마다 입고구 하나씩

- 부지 확장 1(9×9)을 사면 서쪽 벽 `(0,7)`에, 부지 확장 2(12×12)를 사면 `(0,10)`에 입고구가 하나씩 생긴다. 기존 `(0,2)`와 같은 입고구(동쪽으로 내보냄)·벽 출입구·초록 입고 트럭이다. `FactoryGrid.UnlockRegion(9)`/`(12)`에서 만든다(확장 전에는 잠긴 칸이라 충돌 없음).
- 입고구마다 따로 택배를 낸다. 간격 공식은 그대로(`Spawner.IntervalFor`, 배송 수 기준)이고, 입고구마다 자기 타이머를 가진다. 새 입고구의 첫 택배는 생긴 뒤 간격의 절반 뒤에 나와 기존 입고구와 엇갈린다. 입고구 앞이 막혀 내보낼 수 없으면 기존 규칙과 같다.
- 점심시간·퇴근 후 입고 정지, 항공 확률(부지 확장 2 이후 25%)은 모든 입고구에 똑같이 적용한다.
- 저장 v8: 입고구 타이머들을 저장한다(없으면 기본값). v7 이하 저장에서 부지 확장 뒤 `(0,7)`·`(0,10)`에 지어 둔 설치물은 불러올 때 철거하고 설치비 전액 환불, 그 위 택배는 소실(스펙 14.1과 같은 처리).
