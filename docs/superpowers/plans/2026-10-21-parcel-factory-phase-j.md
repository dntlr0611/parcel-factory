# Parcel Factory Phase J — 항공 택배와 항공 트럭 (스펙 §14)

## Task J1 — 코어 (TDD, dotnet + EditMode)
- `CellType`에 `AirOutlet`, `AirReturnDock` 추가(enum 끝에 붙여 저장 호환 유지). `FactoryGrid`에 좌표 상수 `AirOutletX/Y = 11,7`, `AirReturnDockX/Y = 11,9`, `UnlockRegion(12)`에서 두 칸을 도크로 만든다. 도크 판별을 한곳(`IsDock` 같은 도우미)으로 모으고, 출고·반품·도크를 직접 비교하던 곳(ConveyorSim 밀어 넣기, WorkerService 배달·걷기·CanStand, BuildService 해체 금지 등)을 모두 찾아 항공 도크도 같이 처리한다.
- `Package.Air`. `PackageFactory`에 항공 확률 인자(기본 0, 항공 25% 상수), Spawner/GameSession이 부지 확장 2 소유 시에만 0.25를 쓴다. 항공이면 라벨 Method `항공`.
- `DeliveryScoring`: `WrongCarrier`(−10, 실패) 추가, 운송 수단 불일치를 검사 여부보다 먼저 판정. 항공 도크는 대응하는 일반 도크 규칙.
- `SaveSerializer` v7: 택배 `Air`(선택 필드). v6 읽기 유지.
- 테스트: 확장 전 항공 없음/후 25%(결정적 난수), 도크 생성 위치·확장 전 부재, 판정표 전 조합, 레일→항공 도크 배달, 작업자 손 배달, 저장 왕복과 v6 호환.

## Task J2 — 월드와 뷰
- 항공 도크 칸이 생기면 동쪽 벽 출입구와 트럭을 만든다(초록 출고 · 노랑 반품, 기존 트럭 모델과 같은 방식으로 색칠). 트럭 위 비행기 표지판(아이콘 `ui-air`를 쓴 작은 판). 확장 전에는 벽이 막혀 있다. 부지 확장 구매 순간과 세이브 불러오기 둘 다 처리.
- 항공 택배 상자 윗면 마크: `mark-air` 텍스처의 작은 쿼드(투명 컷아웃 또는 Unlit 투명, 빌드에서 셰이더가 빠지지 않도록 `MaterialLibrary` 템플릿 방식). 레일·팔레트·손 모두.
- 검사 카드 배송 방법 `항공` + 아이콘. 프롬프트·상태바·팝업 문구(스펙 14.2~14.3). 조작 도움말에 한 줄.

## Task J3 — 테스트와 스크린샷
- PlayMode: 확장 2 구매 시 도크·트럭 오브젝트 생성, 항공 택배 마크 존재, 틀린 운송 수단 배달 시 −10.
- 스크린샷 `docs/design/unity-air.png`: 12×12, 항공 트럭 두 대, 레일 위 항공 상자와 일반 상자, 작업자가 항공 상자를 들고 초록 트럭 앞(프롬프트 `항공 출고 +30`).

## Task J4 — 분배기·검사기 항공 모드 (스펙 §14.5)
- 코어: `Cell.Mode`(`RouteMode { Inspect, Air }` 등), 검사기 두 번째 출구, ConveyorSim 라우팅(분배기 항공: 검사 모드와 같은 승인/거부 분리, 색만 초록/노랑. 검사기 항공: 검사 후 운송 수단), BuildService 재설정 API(`SetMode`, 검사기 두 번째 출구 설정)와 Plot2 조건, 저장 v7. TDD.
- 입력: R → 3 모드 전환, 검사기 항공 모드에서 R → 1/2 → 화살표. 배너·도움말 문구.
- 뷰: 분배기 항공 모드 화살표 초록·노랑, 검사기 항공 모드 흰색·`#2f86eb`, 검사기의 두 번째 화살표, 미리보기, 미니 상태바 문구.
- 테스트: 라우팅 전 조합, 막힌 출구 대기, 모드 전환 조건(Plot2 전 거부), 저장 왕복, 입력 시퀀스(PlayMode), 스크린샷 `unity-air.png`에 항공 모드 검사기·분배기가 보이는 자동화 줄을 포함.
